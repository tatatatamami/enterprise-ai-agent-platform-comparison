# 顧客向けトーキングポイント
## エンタープライズ AI エージェント基盤：Microsoft Azure AI Foundry

> **対象読者**：プリセールスエンジニア、アカウントエグゼクティブ、ソリューションアーキテクト  
> **目的**：顧客との会話において Microsoft Azure AI Foundry の価値を簡潔・明確に伝えるための説明フレーム

---

## 30秒バージョン（エレベーターピッチ）

### パターン A：エンタープライズ統合重視

> 「Microsoft Azure AI Foundry は、すでに貴社が利用されている Microsoft Entra ID（旧 Azure Active Directory）・Microsoft 365・Teams・SharePoint といった環境にそのまま AI エージェントを組み込める基盤です。新たなセキュリティ設計やユーザー管理の再構築は不要で、既存の IT 資産を活かしながら、社員が日常業務で使うツールの中に AI を自然に埋め込んでいくことができます。」

**使用場面**：既存 Microsoft 環境を保有するエンタープライズ顧客との初回ミーティング

---

### パターン B：セキュリティ・コンプライアンス重視

> 「Microsoft Azure AI Foundry は、エンタープライズ向けセキュリティを標準で内包した AI エージェント基盤です。Entra ID による条件付きアクセス、Azure Monitor による監査ログ、Azure AI Content Safety によるコンテンツ安全性チェックが最初から統合されており、ガバナンス・リスク管理の観点から AI を安心して展開・運用できる環境を提供します。」

**使用場面**：CISO・セキュリティ担当者・コンプライアンス担当者との会話

---

### パターン C：業務改善・ROI 重視

> 「Microsoft Azure AI Foundry と Azure Logic Apps を組み合わせることで、承認フロー・レポート生成・問い合わせ対応といった繰り返し業務を AI エージェントに委譲し、社員がより高付加価値な業務に集中できる環境を構築できます。既存の業務システム（SAP、Salesforce、ServiceNow 等）とも接続でき、組織全体の業務プロセスを段階的に自動化・高度化していくことが可能です。」

**使用場面**：業務部門・経営層との価値訴求シーン

---

## 60秒バージョン（詳細説明）

### パターン A：エンタープライズ統合・段階的 AI 展開

> 「多くのエンタープライズ組織が直面している課題は、AI を導入したいが、セキュリティ・ガバナンス・既存システムとの統合に時間とコストがかかるという点です。
>
> Microsoft Azure AI Foundry はこの課題を解決するために設計された AI エージェント基盤です。中心となるのが **Microsoft Entra ID との統合**です。貴社がすでに持つ Active Directory の認証基盤・アクセス制御ポリシーが、そのまま AI エージェントにも適用されます。新たな ID 管理システムを構築する必要はありません。
>
> また、**Azure AI Search** により、SharePoint・OneDrive・社内データベースといった既存のエンタープライズデータを、ユーザーの閲覧権限を維持したまま AI エージェントに活用させることができます。機密情報へのアクセスを適切に制御しながら、社内ナレッジを最大限に活用した AI エージェントが実現します。
>
> さらに **Azure Monitor** による包括的な監視が標準で統合されており、AI エージェントの動作・コスト・品質をリアルタイムで可視化できます。AI の運用を既存の IT 運用体制にシームレスに組み込むことができます。」

**使用場面**：IT アーキテクト・CTO との技術的な対話

---

### パターン B：競合比較を踏まえた Microsoft の強み

> 「エンタープライズ AI エージェント基盤を選定される際、AWS AgentCore も有力な選択肢として検討されているかと思います。AWS は AWS 環境内での構築・実行においては高い完結性を持つ優れたプラットフォームです。
>
> 一方、Microsoft Azure AI Foundry が特に強みを発揮するのは、**既存のエンタープライズ環境との統合深度**という点です。
>
> 具体的には、**Entra ID** による単一の ID 基盤での認証・認可、**Azure Monitor** による既存監視基盤への統合、**Azure AI Search** によるドキュメント権限を維持したエンタープライズ検索、**Microsoft Fabric** によるデータ分析基盤との接続、**Azure Logic Apps** による業務プロセスとの自動化連携、これらが一つの統合された体験として提供されます。
>
> 貴社が Microsoft 365・Azure AD・Power Platform をすでに活用されているのであれば、その投資を最大限に活かしながら AI エージェントを展開できるのが Microsoft Foundry の大きな価値です。既存システムとの統合コストを最小化しつつ、AI の効果を最大化することができます。」

**使用場面**：競合製品の比較検討が進んでいる顧客との対話

---

### パターン C：AI エージェントの継続的改善・LLMOps

> 「AI エージェントの導入において、多くの組織が見落としがちなのが『運用後の継続的改善』の仕組みです。初期導入は成功しても、AI の品質維持・改善・ガバナンスを継続的に行う体制が整っていないと、長期的な価値を出すことは困難です。
>
> Microsoft Azure AI Foundry は、AI エージェントのライフサイクル全体を管理する **LLMOps（Large Language Model Operations）** の仕組みを提供しています。
>
> 開発・実験フェーズでは、Azure AI Foundry ポータル上でプロンプトフローを設計・テストし、品質評価メトリクスを設定します。CI/CD フェーズでは **GitHub Actions / Azure DevOps** を使ったパイプラインで、テスト・承認・デプロイを自動化します。運用フェーズでは **Azure Monitor / Application Insights** がエージェントの品質劣化を自動検出し、改善のためのフィードバックループを形成します。
>
> このサイクルを組織の中に組み込むことで、AI エージェントは単なる一時的なプロジェクトではなく、組織の継続的な競争優位として機能し続けます。」

**使用場面**：AI の長期運用・ROI 最大化に関心のある経営層・AI 推進担当者との対話

## よくある質問（FAQ）と推奨回答

### Q1：AWS をすでに利用しているが、Azure も追加で導入するのは難しいのでは？

> 「ご懸念はもっともです。ただ、多くのエンタープライズ組織はすでにマルチクラウド環境を採用されています。Azure AI Foundry は AWS との共存も可能で、AI エージェント基盤として Azure を活用しながら、既存の AWS ワークロードを維持するアーキテクチャも実現できます。特に Microsoft 365 と Active Directory をすでに利用されている場合は、Entra ID との統合メリットが非常に大きく、AI 導入の障壁を大幅に下げることができます。」

---

### Q2：Azure AI Foundry と AWS AgentCore のどちらが AI モデルの選択肢が多いか？

> 「両プラットフォームとも、主要な大規模言語モデル（LLM）を幅広くサポートしています。Microsoft Foundry は Azure OpenAI（GPT-4o 等）に加え、Mistral、Llama、Microsoft 独自の Phi シリーズなど多様なモデルをモデルカタログから選択・デプロイできます。モデルの選択肢という観点では両者ともに充実しており、貴社の用途・コスト・性能要件に合わせて最適なモデルを選択できます。」

---

### Q3：コストはどちらが安いか？

> 「両プラットフォームともに従量課金モデルを採用しており、利用量・モデル・リージョンにより価格は異なります。総保有コスト（TCO）の観点では、既存 Microsoft ライセンス（Microsoft 365、Azure EA 等）を保有している組織は、Entra ID・Azure Monitor・Azure DevOps 等の統合コンポーネントを追加費用なしで活用できるケースが多く、トータルコストで優位になる場合があります。詳細は貴社の利用環境に基づいて個別に試算をご提案させていただきます。」

---

### Q4：セキュリティ認証・コンプライアンスの対応状況は？

> 「Microsoft Azure は ISO 27001、SOC 2、PCI DSS、HIPAA、FedRAMP に加え、日本の ISMS（ISO/IEC 27001）にも対応しており、金融・医療・公共機関を含む幅広い業種でのコンプライアンス要件を満たします。また Microsoft Purview によるデータガバナンスと Azure Sentinel による SIEM 統合により、AI エージェントの利用状況を含む包括的なセキュリティ監視体制を構築できます。」
